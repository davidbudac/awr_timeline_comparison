How it works

Aligned windows, scored against their own history

A busy Monday morning is only a problem if it is busier than the last four Monday mornings. The comparison is built on that idea.

Line up the same hour

This Thursday 09:00–10:00 against the twelve prior Thursdays. Weekly, daily or hourly cadence; any window width. The weekly rhythm becomes the baseline instead of the noise.

Score every metric

Load profile, system metrics, wait classes, Top SQL, segment and file I/O: each gets z = (current − μ) ÷ σ over the prior valid windows. Too little history? The report says so rather than guessing.

Read the verdict

A one-line verdict, the biggest movers, and a rule-based “what changed” narrative that links into the section that proves it. Everything else is one scroll away, in a rail.

current Thu 09:00 → 10:00 −1w 09:00 → 10:00 −2w 09:00 → 10:00 −3w 09:00 → 10:00 −4w 09:00 → 10:00 … −12w 09:00 → 10:00
Verdict 21 movers / vs prior 12 windows physical reads ▲ 446% Wait class: User I/O ▲ 319% DB time ▲ 80%

The masthead of the demo report: a release two days earlier flipped one execution plan. The narrative names the SQL_ID and the parameter that changed; SQL Monitor diffs the plan lines.

Fleet console

Many databases, one worst-first page

Point run_awr_fleet.sh at a list of databases. It runs the same comparison against every one in parallel and sorts the rows so the sickest database is first.

One command

fleet.conf — one alias | connect per line
# alias        | connect
prod-emea      | /@PRODEMEA
prod-amer      | /@PRODAMER
reporting      | reporting_ro/@RPT
the whole fleet
./run_awr_fleet.sh fleet.conf

# mark a fleet-wide event on every DB's ASH chart:
MARKERS='2026-04-20 14:00|Applied patch 19.22' ./run_awr_fleet.sh fleet.conf

What you get

  • One dense row per database: status dot, severity score, crit/warn pills, current AAS, its worst finding, a DB-time sparkline and a 24-hour ASH-by-wait-class ribbon. Click to expand into the full detail panel.
  • Failure is loud. Unreachable, timed out, or truncated becomes a red error row sorted to the top. Silence is never mistaken for health.
  • Drill-down built in. Every row prints the exact single-DB command; FLEET_DETAIL=all generates the full reports in the same run.
  • Markers line up. A release or patch is drawn on every database's timeline at the same instant.
  • Offline-complete. Inline SVG only, credentials masked, one relocatable folder per run.

Common runs

# current hour vs the same hour on the 4 prior weeks
./run_awr_trend.sh user/pw@svc

# a specific Monday morning vs the 4 prior Mondays
./run_awr_trend.sh user/pw@svc '2026-04-13 09:00'

# last 4 hours, hour by hour
./run_awr_trend.sh user/pw@svc AUTO 1 4 10 0 1 h

# lean triage report
./run_awr_trend.sh user/pw@svc AUTO 1 4 10 0 1 w simple

# milestones on every dated chart
MARKERS='2026-04-20 14:00|Applied patch 19.22' ./run_awr_trend.sh user/pw@svc

# + day profile (last 24 h vs 7 prior days) + plan-line drift, top 3
./run_awr_trend.sh user/pw@svc AUTO 1 4 10 0 1 w comprehensive Y '' 7 3

# fully offline, self-contained file
ECHARTS=vendor/echarts.min.js ./run_awr_trend.sh user/pw@svc

Inside a report

From verdict to root cause without leaving the page

Screenshots from the demo report: a busy production database over three months, four releases and a patch marked on the timelines.

ASH timelineDB time spanmarkers

The whole span, with your releases drawn on it

Hourly active sessions stacked by wait class from the earliest compared window to now. Releases, patches and incidents ride in as markers, so the question “did it start with the deploy?” is answered by eye. The compared windows are shaded; click a chip in the masthead and they light up everywhere.

findingsz-scoresessential rows

Every number, graded against its own past

The eight biggest movers by |z| first, then each load statistic, system metric and wait class with its prior mean, prior σ, the number of windows it was scored against and the change bucket. Typical rows fold away; Essential rows trims each table to the curated short list; Triage mode hides everything but what matters first.

top SQLper-SQL ASHSQL Monitorplan drift

Down to the statement and the plan line

Top SQL ranked five ways across every window with a bump chart, plan-hash flips badged in the cells, per-SQL ASH stacked by wait event, and SQL Monitor summaries. With sqlmon_detail on, the regressed statement's plan lines are diffed against a prior execution: starts, rows, duration share, memory.
