## What changed between the audit table and the plans

Reading the code closely while writing the plans sharpened several findings:

- **#1 (001)**: the wrapper's `took=` value can contain a space (`1m 05s`),
  so the obvious `\S+` fix would have failed for any extract over a minute.
  The plan's regex was validated against the wrapper's real `printf` formats.
- **#4 (007)**: the correct rule is an *additional* condition, not a
  replacement — replacing it would break snapshot grids at :06–:15 past the
  hour, which the existing snap-back handles today. Truth table in the plan.
- **#5 (005)**: fixed with bash built-ins only (no `awk`): the Docker image
  documents that the wrappers use no awk, and AIX portability favours it.
  A leading-zero value (`08`) fails the same way and is covered.
- **#6 (006)**: section 11 has the same defect with a far lower threshold
  (86 CJK characters in the first 200 of any top statement); included.
- **#7 (010)**: besides never being called, the pruner would delete the
  whole `reports/` directory for a record whose `report_path` is `reports/`
  (confirmed by a failing test in a scratch copy), and dropping a record by
  count orphaned its files. The plan's code and 9 new tests were prototyped:
  137 existing tests pass, 7 of the new ones fail on today's code.
- **#9 (011)**: prototyped the same way (17 existing + 11 new tests).
- **#15 (015)**: measured — GNU `timeout` moves `sqlplus` into its own
  process group, so the server's own `max_run_minutes` kill also leaves
  every `sqlplus` running. `timeout --foreground` (probed) fixes all three
  stop paths without a trap.
- **#16 (016)**: still unverified (no image was built during the audit);
  the plan's first step establishes the fact before changing anything.

## Direction options (not planned — owner's call)

Grounded in the repo; each would be a design/spike plan if selected.

- **Machine-readable run summary.** The server learns per-DB results by
  regex-scraping the wrapper's stdout — the root cause of #1. The wrapper
  already writes `manifest.tsv` / `params.env` into its workdir; a
  `summary.tsv` in the per-run output folder would give the server (and any
  other tooling) a stable contract. Plan 001's contract test is the stopgap.
- **Notify hook on critical / unreachable databases.** The server already
  parses per-DB `crit` / `warn` / ERROR rows on a schedule but has no way
  to tell anyone; an opt-in `[notify] command` run after each scheduled
  fleet run is a small step from "report generator" to "morning check".
  Only useful after 001.
- **Demo + `demo/verify_report.js` as a CI harness for client JS/CSS.** The
  demo exercises every client script without a database; a slow, separate
  CI job (Node + Playwright, about 3 minutes) would catch JS regressions
  that `--check` (plan 014) cannot. Covers JS only, not SQL branches.
- **Move `sql/00_params.sql`'s ~600 literal JS `PUT_LINE`s into the
  `tools/js2plsql.sh` pipeline**, as was done for the timeline / wingrid /
  microstrip scripts: readable source, `node --check`-able. Must stay
  byte-identical.

## Findings considered and rejected

- **Dead-code cleanup** (`is_essential.plsql` / `data-imp`, `.badge.sig`
  CSS, the hidden `td.cell-bar .bg` bar, `day_profile_cte`'s unused CASE):
  removing them changes emitted bytes for no user benefit and breaks the
  byte-identity baseline the project relies on.
- **`window.AWR_setMode` compatibility shim**: tiny, deliberate, protects
  old shared links.
- **Duplicated helpers between the single-DB and fleet code** (`mask_conn`,
  validators, `inline_echarts`, the ASH scan): the "never edit a single-DB
  file for a fleet feature" rule is a deliberate decision; the copies are
  the price.
- **Findings recomputed per section instead of shared**; **section 18's
  seven `DBA_HIST_REPORTS` scans**: documented design decisions (no scratch
  schema, read-only).
- **Non-deterministic rank ties in sections 06/11**: known, documented,
  harmless outside byte-diffing.
- **No lint rule for a semicolon ending a comment in a top-level SELECT**:
  documented as not greppable without false positives.
- **Server has no authentication / binds loopback**: documented posture;
  009 closes the cross-site gap without changing it.
- **Vendored ECharts 5.6.0 vs the CDN's `echarts@5`**: deliberate (offline
  use), with a documented bump procedure.
- **Repository size / tracked example reports**: they are the published
  site's content.
