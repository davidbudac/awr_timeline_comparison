## Why this matters

The report is an Oracle AWR comparison: the Current window against N prior
windows. Two of its lists are ordered by *size*, not by *change*, so the
one row that changed sits below rows that did not:

- **SQL Monitor** (section 18): the per-statement table is ordered by
  Current-window max elapsed. In the demo report the only flagged statement
  (`7k2m9dx4qp1zb`, +23.4σ, plan changed) is the **4th** row, under three
  statements that are within normal (+0.1σ, +0.0σ, −0.5σ).
- **Top SQL** (section 06): every tab ranks by the Current window's size
  (elapsed, CPU, gets, …). The question a comparison report answers is
  "what changed", and only the "Per-exec regression" tab looks at change —
  it misses a statement that runs 10× more often at the same per-call cost.

After this plan, the SQL Monitor table shows large findings, then moderate
ones, then the rest (each group in today's order), and Top SQL opens on a
new first tab, **Biggest change**: statements ranked by Current-window
total elapsed minus the prior-window mean. Which statements are selected
anywhere (top-N, plan cards, Timeline rows) does not change.

### Rules that apply to every SQL edit here

- **Never type a tilde** in a `sql/` file (comments included): `SET DEFINE '~'`
  makes it the substitution character; a stray one prompts for input and
  truncates the section. Write substitution variables only as they already
  appear (`~top_n`, `~weeks_back`).
- **Emitted text is pure ASCII**: HTML entities in markup (`&#9650;`,
  `&times;`), backslash-u escapes in JS. Agent tool input can turn a typed
  backslash-u sequence into the character itself: write such lines from a
  script and check with `grep -nP '[^\x00-\x7F]' <file>` (no output = good).
- Inside a PL/SQL literal a single quote is `''`. Keep every
  `PUT_LINE` source line under 2499 characters.
- Never end a `--` comment with `;` inside the big `FOR s IN (WITH … )`
  query (a SQL statement): it ends the statement early.
- PL/SQL declarations: a new variable goes with the other variables at the
  top of the `DECLARE` section, **before** the `@@sql/lib/…` includes (lint
  check 14).

### Step 4: Add the CHANGE dimension to 06's cursor

In `sql/06_top_sql.sql`, inside the cursor's `WITH` chain, after the
`delta_ranked` CTE (ends at line 247, `AND cur_execs >= 3`) and before
`picked AS (`, add:

```sql
        --
        -- Biggest change: the Current window's total elapsed minus the mean
        -- over the prior VALID windows (a valid window in which AWR kept no
        -- row for the statement counts as 0; a skipped window is not a
        -- window here at all).  Regressions only.  Same agg as every other
        -- dimension: no extra DBA_HIST_SQLSTAT read.
        --
        n_prior_valid AS (
            SELECT COUNT(DISTINCT week_offset) AS n
            FROM   valid_windows
            WHERE  week_offset > 0
        ),
        chg_ranked AS (
            SELECT sql_id, cur_ela, prior_mean,
                   ROW_NUMBER() OVER (ORDER BY cur_ela - prior_mean DESC, sql_id) AS r_chg
            FROM (
                SELECT a.sql_id,
                       SUM(CASE WHEN a.week_offset = 0 THEN a.elapsed_time_delta_us END) AS cur_ela,
                       NVL(SUM(CASE WHEN a.week_offset > 0 THEN a.elapsed_time_delta_us END), 0)
                           / NULLIF((SELECT n FROM n_prior_valid), 0) AS prior_mean
                FROM   agg a
                GROUP BY a.sql_id
            )
            WHERE  cur_ela > prior_mean
        ),
```

(`NULLIF` makes `prior_mean` NULL when there is no prior valid window, so
`cur_ela > prior_mean` is never true and the dimension is empty.)

Add a branch at the end of `picked` (after the PEREXEC branch, before the
closing `),` of `picked` at line 282):

```sql
            UNION ALL
            -- CHANGE: per-window total elapsed for the top-N statements by
            -- the change above; rnk only at week_offset 0 (like PEREXEC)
            SELECT 'CHANGE' AS dim, a.week_offset, a.sql_id, a.plan_hash_value,
                   a.elapsed_time_delta_us AS metric_value,
                   CASE WHEN a.week_offset = 0 THEN cr.r_chg END AS rnk
            FROM   agg a
            JOIN   chg_ranked cr ON cr.sql_id = a.sql_id
            WHERE  cr.r_chg <= (SELECT top_n FROM run_params)
```

columns; `ord` 0 makes CHANGE sort first):

