## Why this matters

Section 11 ("Top SQL activity", `section#topsql-ash`, shown only in the
*All sections* view) draws one ECharts stacked-area chart per Top-N SQL
statement — up to 30 — over the whole compared span, all at page load.
Measured on the demo report (`docs/examples/demo_busy_db.html`, Chrome,
1440 px, 4 runs, by wrapping `echarts.init` / `setOption` in Playwright):

| | with section 11 as today | section 11 charts disposed |
|---|---|---|
| ECharts `setOption` time at load (all 39 charts) | ~670 ms, of which **~295 ms** are the 17 section-11 charts | — |
| first switch from Summary to All sections | **~1.5 s** | **~0.74 s** |

In the default Summary view section 11 is hidden (`display:none`), yet its
17 charts are initialised at load and then all resized at once when the
reader first opens All sections. On a real database with 168 hourly windows
(an 18–19 MB report) every chart carries thousands of buckets, so the cost
grows. Drawing a chart only when it is about to scroll into view removes
that work from page load and from the view switch; a reader who never opens
All sections never pays for it.

## Current state

Background:

- The report is produced by SQL\*Plus; `sql/11_top_sql_ash_breakdown.sql`
  prints its HTML and an inline `<script>` with
  `DBMS_OUTPUT.PUT_LINE('…')`. JS lives inside PL/SQL string literals: a
  single quote is `''` (the file uses double quotes in JS), and a tilde must
  never appear anywhere (`SET DEFINE '~'`; it becomes a substitution
  prompt and truncates the section).
- **Emitted text is pure ASCII** (lint check 25). The file already writes
  `"—"` as a backslash-u escape; keep any such escape as it is. Agent
  tool input can turn a typed backslash-u sequence into the character
  itself: check with `grep -nP '[^\x00-\x7F]' sql/11_top_sql_ash_breakdown.sql`
  (no output = good).
- The section's script runs **while the page parses** (it is an inline
  `(function(){ … })();`, not a DOMContentLoaded handler). By then the
  early view script has already set `body.vs` / `body.vt` / `body.va`, so a
  chart in a hidden view has `offsetParent === null`.
- Do **not** use `IntersectionObserver` or `requestAnimationFrame` here:
  `sql/00_params.sql:589-592` records that embedded webviews throttle both
  "to a standstill"; the report's scrollspy uses a throttled scroll
  listener for that reason. Follow the same approach.
- The chrome dispatches `document` event `awr:view` on every view switch
  (`sql/00_params.sql:1057`) and `awr:window` / `awr:theme` for window
  highlight and theme flips.

The script, `sql/11_top_sql_ash_breakdown.sql:475-622`: payload

### Step 1: Wrap the per-chart init in a function

In `sql/11_top_sql_ash_breakdown.sql`, change line 589
`DBMS_OUTPUT.PUT_LINE('(d.charts||[]).forEach(function(c){');` and the lines
after it as follows (body unchanged except the three marked edits):

1. Just **before** line 589 add the window-highlight state shared by charts
   that are initialised later:

   ```sql
    -- plan 035: charts are drawn when they come near the viewport, so a
    -- window highlighted before that must still be applied at init
    DBMS_OUTPUT.PUT_LINE('var hiNow=null; document.addEventListener("awr:window",function(e){hiNow=e.detail?e.detail.w:null;});');
   ```
2. Replace line 589 with
   `DBMS_OUTPUT.PUT_LINE('function initChart(c){');`
3. In the function body, change `var el=document.getElementById(c.id); if(!el) return;`
   to `var el=document.getElementById(c.id); if(!el||el.getAttribute("data-init")) return; el.setAttribute("data-init","1");`

   (a chart drawn after a dark-mode toggle must use the current palette;

5. Replace the closing `DBMS_OUTPUT.PUT_LINE('});');` of the old `forEach`

### Step 2: Initialise on demand

Right after the new `}` that ends `initChart` (still before
`DBMS_OUTPUT.PUT_LINE('})();');`), add:

```sql
    -- On demand: a chart is drawn once its card is visible (its view is
    -- shown) and within 600px of the viewport.  A throttled scroll /
    -- resize check, not IntersectionObserver (embedded webviews throttle
    -- it, see 00_params.sql's scrollspy note); also on a view switch, any
    -- click (details, tabs, links), page load and before printing.
    DBMS_OUTPUT.PUT_LINE('var pend=(d.charts||[]).slice(), tmr=null;');
    DBMS_OUTPUT.PUT_LINE('function near(el){if(!el||el.offsetParent===null)return false;var r=el.getBoundingClientRect(),h=window.innerHeight||800;return r.bottom>-600&&r.top<h+600;}');
    DBMS_OUTPUT.PUT_LINE('function check(){pend=pend.filter(function(c){var el=document.getElementById(c.id);if(!el)return false;if(near(el)){initChart(c);return false;}return true;});}');
    DBMS_OUTPUT.PUT_LINE('function soon(){if(tmr||!pend.length)return;tmr=setTimeout(function(){tmr=null;check();},120);}');
    DBMS_OUTPUT.PUT_LINE('window.addEventListener("scroll",soon,{passive:true});window.addEventListener("resize",soon);window.addEventListener("load",soon);');
    DBMS_OUTPUT.PUT_LINE('document.addEventListener("awr:view",soon);document.addEventListener("click",soon,true);');
    DBMS_OUTPUT.PUT_LINE('window.addEventListener("beforeprint",function(){pend.forEach(initChart);pend=[];});');
    DBMS_OUTPUT.PUT_LINE('check();');
```

Notes: `check()` runs once now (the cards are already parsed); hidden
cards stay pending. `initChart` is idempotent (`data-init`). Printing from
Summary still prints no section 11 (it is hidden there, as today).
